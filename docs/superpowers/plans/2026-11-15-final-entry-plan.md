## 四、唯一还需要你拍板的技术决策：`mode=off` 的"不联网"到底指什么

今天核实到的事实：`chat.ts:141` 的 `nvdLive()` **不看 `wantWeb`**——也就是说当前线上这版在 `mode=off` 下就已经会去请求 NVD。Task 3 的 `kevCatalog()` 接上之后同理（现查 CISA，1.8 MB 目录）。而 UI 与文案给人的印象是"off = 不联网"。两个选择：

**A. 维持现状 + 把话说清楚（推荐）。** `off` 关的是**对话式联网检索**（DashScope `enable_search`），不关结构化权威源的编号核对（NVD / CISA KEV）。理由：① 这是今天的真实行为，改代码等于削掉第 10 条缺陷唯一的解药；② KEV 目录是这道旗标题唯一能答全的来源，`off` 下禁掉它，旗标题在演示里就只能答"仅一条"；③ 措辞可控。代价：要把 `note` 与作品帖的说法统一成"关闭对话式联网检索；仍会核对 NVD/KEV 权威目录"，这属于**用户可见文案改动**，和 Task 6 是同一批。

**B. 严格化：`off` 一律不出网。** 契约最干净，但旗标题在 `off` 下必然答不全——目录里 2026 年的 Office 条目有 5 条，本地库只有 4 条（`CVE-2026-124194` 收录于 2026-11-10，本地 KEV 快照停在 2026.11.09），而今天实测**连库里那 4 条也只送得到 1 条**，除非再加一个每日刷新 KEV 入库的定时任务——那是新增基础设施，不在剩余 15 天的预算里。

我按 A 写进计划与文档；你要 B 就说一声，我把 Task 4/6 的判据反过来，并在作品帖里如实写"`off` 模式下旗标题不完整"。

### 0b. 命令一律走 npm 脚本，不要在命令行里拼 shell 语法

11-15 有人**在 `cmd.exe` 里**照抄本文件早先给的 bash 命令，三条翻了车，其中一条最危险：

- `SKIP_LLM=1 npm test 2>&1 | tail -6` 在 cmd 里既不赋值环境变量、也没有 `tail`，**整条静默不执行**，输出是空的——"没报错"被当成"通过了"。掉线的检查比红掉的检查更危险。
- `git archive ... -- . ':(exclude)docs/superpowers'` 里的单引号与续行反斜杠被 cmd 原样吞掉，报 `could not open '/f/Qoder/...' for writing: No such file or directory`（`/f/...` 是 Git Bash 的路径写法）。
- `python - <<'PY'` 那种 heredoc 在 cmd 里是 `此时不应有 <<。`。

所以这三步各自收进一个 Node 脚本，走 `spawn` 传参数数组、不过 shell，**cmd / PowerShell / Git Bash 里都是同一条命令、同一份语义**：

```
cd /d F:\Qoder\seccopilot           （Git Bash 里是 cd /f/Qoder/seccopilot）
npm run test:offline                → 脚本内强制 SKIP_LLM=1，零网络零模型费用
npm run submit:package              → git archive HEAD 打包 + 打印路径/大小/sha256
npm run submit:audit                → 审计将要进包的每个 blob
npm run submit:audit:selfcheck      → 证明审计判据自己能判红（18 项）
```

`npx tsc -p tsconfig.functions.json` 那条本来就跨 shell，可以直接用；`npm run check:function` 是它的别名。

### 2. 打提交包并审计

```
npm run submit:package
npm run submit:audit
```

`npm run submit:package` 内部就是 `git archive HEAD`——只装**已跟踪且已提交**的文件，所以 `data/.env`、129 MB 数据、`node_modules`、`.superpowers/` 结构上就进不来；打完立刻用 `npm run submit:audit` 扫一遍 HEAD 的每个 blob（6 种凭据形状 + 6 条禁止路径 + 2 MB 体积上限），预期 `凭据/禁止项命中：0`、`data/.env 在包里的条数：0`、结论行 `可以上传`。

这一步不能省，也不能只凭"我记得没带"。**判据自己也要被证明能用**：`npm run submit:audit:selfcheck` 同时钉两个方向——6 条凭据判据各有必须命中的合成样本、7 条禁止路径必须命中、11 条良性样本零误伤（11-15 实跑 18 项全过）。这套自检上线当天就抓到三处我自己的错：`supa_svc_role` 那条判据因为 `\b` 后面接下划线没有词边界而**永远不命中**（这里刻意不写那条判据的完整字面串——审计会扫每个 blob，包括这份文档自己，写了就把自己判成"不要上传"）、连接串正则要求冒号紧跟 scheme 所以**永远不命中**、还有一条 `^dev/.*\.md` **误伤**了 `.gitignore` 显式放行的 `dev/README.md`，让脚本把自己仓库判成"不要上传"。前两条是哑判据，第三条是假阳性，两类都会让人对着绿色结果放心。
