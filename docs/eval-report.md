## 判分口径

- **知识库内题**：回答引用的知识库来源中出现期望编号或权威域名即通过（不要求措辞一致）。
- **时效性题**：回答必须命中下方“时效题基准”里已核验的具体事实；把话题相近的其它编号答进来不算对（例：问 Log4j 却给 Tomcat 的 CVE-2026-34486）。明确承认“无法确认本周/知识库未覆盖”同样算通过——这类题考的是时效覆盖，不是措辞。KEV 那道还额外要求漏洞类型与官方名对得上（`title` 判据），防“编号真、类型挂错”；这条是**预防性收紧**，不是修已测到的缺陷——`node dev/check-title-criterion.mjs` 重算四份留档那道题的 8 行，判定翻转 0 行，且判分器本身由 `node scripts/eval.mjs --selfcheck` 用 7 条合成样本钉住（含 3 个必须判红的方向）。
- **知识库外题**：回答出现明确的未覆盖/无法确认表述即通过；这是幻觉防线，不是检索能力。
- **域外可答题**：问题本身合法但不在安全知识库范围（如找回 WiFi 密码），允许正常回答，判据是不得冒出来源里没有的安全编号。
- **可疑编造编号**：回答里出现 CVE/CWE/T 编号，但所有来源的标题与 URL 都没有该编号。已排除两类误报：问题里本来就带的编号（复述回来是正确行为）、以及父技术被引用的子技术编号。`off` 模式下这项仍需人工确认——本地条目正文里合法引用的其他编号也会出现在回答中，而响应只回传来源标题以控制体积。
- 自动判分只覆盖形式正确性，语义质量仍需抽查回答正文。
